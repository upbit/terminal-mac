# 手机只读观察页: 开发与验收方案

> 当前本地调试首版以 [PHONE_OBSERVER_DECISIONS.md](PHONE_OBSERVER_DECISIONS.md) 的收敛决策为准。下文保留完整设计基线，不作为本轮全量实现范围或已验收声明。

状态: 设计基线, 尚未实现或完成真机验收。本文中的性能数字分为本地合成图编码结果、计算示例和待验收目标, 不应相互替代。

## 1. 决策与范围

面向屏幕大部分时间不变、手机偶尔查看的场景, 采用 **HTTPS/WSS + 二进制 PNG 图片 + tile 差分 + Canvas**。小窗与全屏复用同一协议, 全屏只提升目标分辨率和帧率上限, 不自动切换 WebRTC。

首版必须具备:

- 小窗查看、点击放大、退出放大、本地缩放和平移, 均不向 Guest 注入输入。
- 首次完整画面, 后续仅更新变化块; 静止时不编码和发送重复图像。
- 每个客户端独立的确认基准、背压、重连和完整刷新机制。
- 屏幕录制权限不足、Guest 不可用、VM 暂停/停止、断网、后台恢复的明确状态。
- 显式开启的只读 Host 服务、访问鉴权、Guest 隔离和资源上限。

不包含远程点击/键盘/剪贴板/文件传输、音频、录像、历史回放、OCR、WebRTC、自动公网发布。手机访问不能启动/恢复 VM 或代替用户授予权限。持续滚屏和视频作为退化压力场景, 不承诺视频级流畅。

本文所有新命令、文件名和消息均为拟议接口, 并非当前已存在的能力。

## 3. 数据流与所有权

```text
Guest: ScreenCaptureKit 观察流
  -> 最新完整像素缓冲 + captureEpoch/captureSeq + 脏区历史
  -> virtio-fs Mailbox (完整 BGRA/LZ4 + 累计脏区元数据)
Host: 每 VM 一个采集协调器
  -> small/detail 两档完整像素快照 + tile revision 表
  -> 每手机连接自己的 epoch/已确认 revision 表/一个在途批次
  -> WSS 二进制 PNG 批次
Phone: 解码完整批次 -> Canvas 原子提交 -> ACK
```

首版优先节省 **Host -> 手机** 的网络流量。Guest -> Host 可以继续传完整 BGRA/LZ4, 不要求第一版就在共享目录实现像素差分。需要分别测量这两段字节数与开销, 不能把公网带宽节省宣称为 Guest 本地 I/O 同比例减少。

- 每 VM 只保留一个 Web 观察采集流, 与原终端流隔离; 无手机时不启动。
- Web 采集源按所有可见观察者需求的最高档配置, Host 派生最多 small/detail 两份图。同档客户端共享图像生成, 但不共享 ACK 状态。
- 关闭一个手机连接不能停止其他观察者或终端查看器; 低档请求不能降低仍在使用的高档源。
- 通过每 VM 的本地独占锁避免多个 Host 观察服务重复占用 Guest 观察流。Guest 侧观察会话带租约; Host 崩溃后能够自动回收。

### 3.1 默认参数

以下是初始配置, 需由第 11 节的实测确认或修订。

| 项目 | small | detail |
| --- | --- | --- |
| 图像长边上限 | 640 px | 1600 px |
| 有变化时的发送上限 | 2 FPS | 5 FPS |
| tile | 128 x 128 px, 边缘裁切 | 相同 |
| 静止时图像发送 | 0 FPS | 0 FPS |
| 默认编码 | PNG | PNG |
| 预期用途 | 观察状态和布局 | 阅读文字和细节 |

保持 Guest 宽高比、不裁切、不超过源像素尺寸。部署可将 detail 提至 1920 长边, 总像素硬上限为 2,073,600; 缩放因子同时受长边、像素数和原尺寸限制, 向下取整到有效偶数。浏览器 CSS 尺寸和 DPR 不等于传输尺寸, 首版不直接按 DPR=3 申请三倍宽高。全屏不改变 Guest 显示器分辨率。

当只剩低档观察者时, 采集配置降档延迟 2 秒以减少抖动; 升档及时执行。模式请求去抖 200 ms, 连续请求只保留最终目标。手机横竖屏仅改变本地布局, 不因每次 `resize` 都重建采集流。

## 4. dirtyRects、缩放与像素正确性

`SCStreamFrameInfo.dirtyRects` 是变化区域提示, 不是独立可解码补丁, 也不是滚动复制命令。它描述捕获序列的变化, **不描述某个手机最后显示的画面**。

### 4.1 Guest -> Host 连续性

新增观察能力协商和固定请求 `observe.open`、`observe.poll`、`observe.close`, 不改变旧 `screenshot` 语义。能力响应至少声明协议版本、dirtyRects 是否可用和尺寸上限。旧 helper 不支持时明确提示升级, 不悄悄复用会干扰终端尺寸的旧流。

`observe.poll` 传入租约 ID、`captureEpoch`、`afterCaptureSeq` 和有上限的等待时间。一次有效响应需原子绑定:

- 不可变的最新完整缓冲及其 `captureSeq`、尺寸、像素格式、颜色空间。
- 从 `afterCaptureSeq` 到该缓冲序号之间所有脏区的并集, 或 `dirtyCoverage=full`。
- 配置代次 `captureEpoch` 与捕获状态。无新内容可以回复 `unchanged`, 但必须更新租约并允许检查流错误。

保留最多 128 条/60 秒的元数据记录, 不保留同等数量的像素缓冲。记录淘汰后客户端的基准若太旧, 返回 `dirtyCoverage=full`。历史记录过碎时直接标记 full, 不扩张为无界矩形列表。首次、配置改变、流重建、基准不匹配、无法证明连续性的跳帧、元数据缺失/无效时都扫描完整图。

`observe.poll` 的等待上限为 1000 ms, 同一租约最多一个在途请求; Guest 租约在最后一次有效续租后 15 秒过期。Host 必须持续续租但不阻塞原输入处理, long-poll 应独立调度。Web 源的捕获上限与当前最高档的 2/5 FPS 对齐, 不固定保持原终端流的 30 FPS。

低 FPS 下, A 之后跳过 B/C 再发送 D, 必须累计 B/C/D 的变化, 并从 D 的完整缓冲取像素。不能只保存 D 自身的 dirtyRects。正常 idle 状态不应伪造新图; 非完整帧不作为补丁来源。发生流错误时即使仍缓存旧缓冲, 也不能继续报告为健康实时画面。

保留或复制缓冲必须有明确所有权, 在回调外使用时确保其生命周期正确; 不在 SCK 回调或全局锁内压缩 PNG。当前流错误、改尺寸、旧回调晚到的情况需按代次隔离, 不能把旧流帧标成新配置。收到与新配置相符的完整帧后才发布新代次。

### 4.2 Host 归一化

统一为 sRGB、8-bit 不透明 RGBA、左上角原点、整数输出像素坐标。明确定义 BGRA 转 RGBA、stride、alpha 和色彩转换, 不把源行末 padding 当作可见像素比较或发送。LZ4 解压前验证 `bytesPerRow * height` 的溢出和硬上限, 使用有输出上限的解压 API。

对 dirtyRects 的坐标空间通过目标系统实测确认, 结合 `contentRect`、`contentScale`、`scaleFactor` 和实际像素尺寸建立映射, 禁止无条件乘 Retina 倍率。矩形裁到有效边界, 小数边界向外取整。二次缩放的插值会影响相邻像素, 必须按已选滤波核扩展候选区, 再对齐 tile; 未确定映射或核范围时按 full 扫描。

先在目标分辨率对候选 tile 做像素比较, 再压缩真正不同的 tile。哈希只能用于加速, 相等哈希需字节比较确认, 或另有经过论证的正确性保障; 单靠弱哈希不能决定不更新。

即使候选区覆盖全屏, 最终像素完全相同也不发送。全屏扫描用于完整性兜底, 不等于强制发完整 PNG。

### 4.3 Host -> 手机基准与背压

每档 Host 快照包含完整像素和每个 tile 的单调 `revision`。tile 内容相对上一份该档快照变化时才递增 revision。每个连接有独立的 `ackedRevisions` 和最多一个 `inFlight`。

```text
publishCapture(snapshot):
  原子发布该档最新完整图和 revision 表
  唤醒有变化、达到发送间隔且没有 inFlight 的连接

buildBatch(client):
  固定当前快照及其 revision 表
  找出 currentRevision != ackedRevision 的 tile
  从这份快照编码, 生成 seq/baseSeq 和 inFlightRevision 表
  完整登记 inFlight 后交给 WebSocket 发送

onAck(epoch, seq):
  只接受当前在途批次的确认
  将该批次携带的 revision 合入 ackedRevisions
  清除 inFlight, 再从最新快照判断下一批
```

发送期间发生的新变化仍保留在最新快照及 revision 表中。ACK 不能把 `ackedRevisions` 整体替换成 ACK 到达时的最新版, 否则会漏掉编码/发送期间的变化。补丁总是源像素的替换图像, 不是 XOR 差值。

编码中也占用唯一在途槽, 在异步编码前先预留, 避免并发捕获回调启动多个批次; 编码失败释放槽并进入恢复。full 的确认更新该快照全部 tile 的 revision, delta 只更新其携带的 tile。因 FPS 限制延后的变化必须设置下一次可发送时刻的定时器, 不能只等新捕获事件唤醒, 否则最后一次变化可能永远未显示。

同一连接不积压完整帧队列, 不在 `bufferedAmount` 增大后继续发旧画面, 也不能任意丢掉已发送补丁的依赖。ACK 窗口为 1 会使吞吐受 RTT + 解码时间限制, 接受它作为低 FPS 首版的取舍; 不承诺 300 ms RTT 下仍达到 5 FPS。

revision 溢出、配置重建或状态丢失时重置代次并发 full。客户端不同 ACK 速度只影响自身, 不能阻塞其他连接。

`epoch` 切换要撤销旧代次的编码任务与待发送批次, 但已经交给 TCP 的字节无法撤回。`welcome` 必须先于新代次的 full, 接收端按代次丢弃迟到任务; 设置模式不能绕过背压, 连续切换不得各自积压一张 full。配置切换遇到不可写 socket 时等待或关闭连接, 不继续追加图片。

## 5. PNG/JPEG 大小与带宽

### 5.1 编码选择

- PNG 是首版必选编码: 无损、浏览器原生支持、适合文字和均匀色块, tile 边界可精确拼接。
- JPEG 不保证总是更小。尺寸取决于图像熵、缩放抗锯齿、色度采样、质量和编码器; 同一质量数字不能跨编码器等同。
- JPEG 在图片类内容上通常更省, 但小字和彩色字边缘会有损失; 即使高质量 JPEG 也不是无损。PNG 更大时也应同时比较可读性。
- 画质对照固定同一源和分辨率, 在实际显示倍率及 2x 局部放大下检查黑白字、彩色字、细线和 tile 接缝; 再比较 PNG 与 JPEG Q75/Q90 的字节数。不能用降低分辨率得到的 JPEG 与原分辨率 PNG 直接归因比较。
- 首版不实现自动 PNG/JPEG 混合 tile, 避免画质不一致、接缝和有损基准管理。预留 `codec` 字段; 后续可加入用户明确选择的省流整帧 JPEG 模式, 必须单独验收。
- 若未来加入有损模式, 每次从源完整像素重新编码, 不把已解码 JPEG 作为下一轮编码源; 切回无损要 full 覆盖旧有损画面。
- WebP 作为后续候选, 先确认 Host 编码库、成本和目标浏览器支持, 不假定 ImageIO 自带所需 WebP 编码能力。

### 5.2 可复现的本地样本

配套 [phone-observer-codec-benchmark.swift](phone-observer-codec-benchmark.swift) 使用 CoreGraphics/CoreText 生成固定 1600 x 1000 合成图, 再缩到 640 x 400; ImageIO 编码 PNG、JPEG quality=0.75/0.90。未调用屏幕捕获、未读取真实桌面内容。图片包含 sRGB 编码元数据, 统计最终文件字节。

测量环境: macOS 15.7.3 (24G419), arm64, Apple Swift 6.2。字体和系统编码器版本会影响结果。以下不是实际 Guest 工作负载或端到端吞吐测试。

| 合成场景 | 分辨率 | PNG (KiB) | JPEG Q75 (KiB) | JPEG Q90 (KiB) |
| --- | --- | ---: | ---: | ---: |
| 终端日志 | 640 x 400 | 146.2 | 64.1 | 78.4 |
| 终端日志 | 1600 x 1000 | 297.2 | 267.6 | 326.1 |
| 表格状态页 | 640 x 400 | 89.7 | 51.8 | 64.6 |
| 表格状态页 | 1600 x 1000 | 207.7 | 197.4 | 245.3 |
| 高熵图像对照 | 640 x 400 | 369.5 | 78.4 | 103.4 |
| 高熵图像对照 | 1600 x 1000 | 2306.5 | 778.8 | 953.2 |

高熵对照是带确定性噪声的程序生成图, **不是真实照片或视频**, 仅说明内容会改变压缩比例。小尺寸终端字样较小, 只代表预览, 不能以这些图证明手机全文阅读体验达标。

单个 128 x 128 裁剪块也有固定开销。此样本的 640 宽终端块为 PNG 5,778 B / JPEG Q75 3,107 B; 1600 宽终端块为 PNG 1,867 B / JPEG Q75 1,565 B。这是不同缩放图中某一个固定位置的块, 不是平均块大小, 也不是已测得的真实增量负载。

复现命令, 从仓库根目录运行; 图片仅写入指定输出目录, CSV 输出到终端:

```bash

```

### 5.3 从图片大小计算带宽

```text
平均图像码率 (bit/s) = 8 * 实际图像消息字节总和 / 观察秒数
单批大小 = 固定头 + JSON 元数据 + 所有 PNG tile 字节
会话流量 = 首次 full + 所有 delta + 重同步 full + 控制消息 + 网络协议开销
```

KiB = 1024 B; Mbps = 1,000,000 bit/s; 下表每小时流量用十进制 MB。按编码文件大小计算, 未计 JSON、WS、TLS/TCP/IP、重传、首帧和额外刷新:

| 计算假设, 不代表真实运动序列 | 图像码率 (Mbps) | 持续一小时 (MB) |
| --- | ---: | ---: |
| 640 宽终端, 整帧 PNG, 每秒 2 次 | 2.395 | 1077.7 |
| 同图整帧 JPEG Q75, 每秒 2 次 | 1.051 | 472.9 |
| 每次仅发送该 5,778 B PNG 块, 每秒 2 次 | 0.092 | 41.6 |
| 1600 宽终端, 整帧 PNG, 每秒 5 次 | 12.174 | 5478.1 |
| 同图整帧 JPEG Q75, 每秒 5 次 | 10.959 | 4931.6 |
| 每次仅发送该 1,867 B PNG 块, 每秒 5 次 | 0.075 | 33.6 |

这里的块大小不能外推到所有块。差分协议、tile 数量和实际事件频率往往比 PNG 改 JPEG 更影响总流量。静止时不是按表中 FPS 持续发送; 光标闪烁、时钟、进度条则是真实变化, 不计作完全静止。带宽规划至少为实测应用层流量留出 20% 余量, 这不是协议开销固定为 20% 的承诺。

### 5.4 整帧回退与限流

- 先像素去重, 再根据变化 tile 的并集面积计算覆盖率, 不累计重叠矩形面积。
- 初始候选阈值为 40% 覆盖率或 64 个变化 tile。跨过阈值时评估 full; 不将其视为普适最优点。
- 缓存允许时比较 `full PNG + full 头` 与 `tile PNG 总和 + delta 头`, 发送较小者。基准缺失时无论大小必须 full。
- 编码成本过高时可根据近期同档统计提前选择 full, 但必须记录选择原因并在回放数据中验证没有持续增大字节数。单个快照最多做一轮候选编码, 不无限试质量参数。
- 以 5 秒窗口记录每连接发送字节和 ACK 时间; 稀疏场景优化目标为 small <= 0.25 Mbps、detail <= 1 Mbps, 不是所有内容的硬承诺。
- 超预算先降低发送频率 (5 -> 2 -> 1 FPS), 将期间变化合并为最新快照; 同时遵守单在途批次。仍不满足时提示网络状态, 不悄悄把文字改成低质量 JPEG。用户可返回小窗。
- 如果未来要强制计费流量上限, 需单独定义包含首帧/重连在内的 token bucket 与降分辨率策略, 不把本节的目标平均值称为硬带宽上限。

## 6. 浏览器协议 v1

### 6.1 控制消息

控制使用 UTF-8 JSON, 图像使用二进制 WebSocket 消息。一个连接同时仅订阅一个授权 VM、一档画面。`epoch` 为随机 UUID 字符串, `seq`/`baseSeq` 为十进制字符串, 防止 JS 64-bit 整数精度丢失。尺寸、偏移和长度为受限整数。

| 方向 | 消息 | 核心字段与语义 |
| --- | --- | --- |
| C -> S | `subscribe` | `v:1`, `mode:small/detail`; 服务已绑定 VM, 不接受路径或任意 VM 名 |
| S -> C | `welcome` | `v`, `epoch`, `width`, `height`, `tileSize`, `codec:png`, `maxFps`; 本代次待 full |
| C -> S | `ack` | `epoch`, `seq`; 完整批次成功提交到 Canvas 后发送 |
| C -> S | `resync` | `epoch`, `lastSeq`, 受限原因枚举; 放弃当前代次并要求新 full |
| C -> S | `setMode` | `mode`; 实际配置变化时换 epoch, 先 full |
| C -> S | `pause` / `resume` | 隐藏页面暂停图像; 恢复使用新 epoch 和 full |
| 双向 | `ping` / `pong` | 有界 nonce, 每 15 秒; 不带图片, 不充当 Guest 健康证明 |
| S -> C | `state` / `error` | 固定状态码、是否可重试, 不带路径/凭证/内部异常堆栈 |

只接受已知字段、版本、枚举和当前状态允许的消息。客户端不能设置编码路径、采集对象、FPS 上限或 Host 资源限制。旧 epoch 的迟到 ACK 忽略, 完全重复的最近 ACK 可幂等忽略; 未发送过的当前 epoch 序号或非法状态转换作为协议错误, 不能推进基准。

### 6.2 图像批次格式

一个完整逻辑 WebSocket binary message 是一个提交单位。WS 库负责网络分片重组和累计大小限制。

PNG 本身已压缩, v1 不启用 `permessage-deflate`, 避免重复压缩的 CPU/内存开销。只传二进制, 不使用 Base64 (其正文大小通常约增加三分之一)。

| 偏移 | 类型 | 含义 |
| --- | --- | --- |
| 0 | 4 bytes | ASCII `TMOB` |
| 4 | UInt16 big-endian | 版本 1 |
| 6 | UInt16 big-endian | flags, v1 必须为 0 |
| 8 | UInt32 big-endian | 后续 UTF-8 JSON 头长度 |
| 12 | JSON bytes | 下述元数据 |
| 12 + headerLength | bytes | 顺序拼接的 PNG 文件 |

示意元数据, `length` 只是格式示例, 不能作为测试 golden payload:

```json
{
  "type": "delta",
  "epoch": "459d11da-fc80-490e-a7a8-7b670cc93a03",
  "seq": "12",
  "baseSeq": "11",
  "width": 640,
  "height": 400,
  "codec": "png",
  "blocks": [
    {"x": 128, "y": 128, "w": 128, "h": 128, "offset": 0, "length": 5778}
  ]
}
```

`offset` 相对于拼接图片区。delta 块不重叠, 按行列排序, 除边缘块外与 tile 网格对齐。每张 PNG 的实际宽高必须等于块声明, 所有数据长度和累加需验证, 不接受重叠载荷、空块或尾随未声明数据。PNG 头声明的尺寸也须在交给浏览器解码器前校验, 不能等解码分配内存后才发现超大图片。

`full` 为一个覆盖整个输出的块, `baseSeq:null`, 清除旧图后替换; 同 epoch 下也允许用 full 代替一次昂贵 delta。首次 full 的 `seq="1"`, 后续发送批次逐一递增。`delta.baseSeq` 必须等于该客户端最后成功提交的 `seq`, 不等于源捕获序号。

### 6.3 限制与恢复

| 限制 | 首版值 |
| --- | --- |
| 单控制消息 | 8 KiB |
| 二进制 JSON 头 | 64 KiB |
| 完整二进制消息 | 12 MiB, 含头 |
| 输出 | 长边 <= 1920, 像素数 <= 2,073,600 |
| 单 delta 块数 | <= 256 |
| 每连接在途图像批次 | 1 |
| 每 VM 连接数 | 4, 超限明确拒绝 |
| Host 当前档编码缓存 | 合计 <= 32 MiB, 仅近期版本, 可淘汰 |
| 客户端并行图片解码 | <= 4, 总解码像素也须受完整帧上限约束 |
| ACK 超时 / 心跳超时 | 10 秒 / 45 秒 |
| 已知无可见订阅后停止 Web 捕获 | <= 15 秒 |

12 MiB 是安全上限, 不是合理的日常消息大小。超限帧不得截断传输; 返回受限错误并降档重建, 仍超限则停止该订阅。服务端监视 socket 的待写队列和不可写状态, 保持最多一个有限消息; 浏览器的 `bufferedAmount` 只反映浏览器自身发送队列, 不能用来推断 Host -> 手机拥堵。

ACK 超时关闭连接并释放在途数据。自动重连基础等待为 1/2/4/8/15 秒, 每次加 0 到 2 秒随机抖动, 总等待最多 17 秒; 新连接始终 full, 不复用旧 Canvas 基准。连续因超大首帧/弱网超时可在同一授权会话下退回 small 并报告原因; 不能无限全分辨率重试消耗流量。

正常静止不定时强制发送 full。重连、解码失败、基准失配、配置改变、Canvas/context 丢失和恢复前台触发 full。网络恢复后不补播断线期间的画面。

## 7. 手机端呈现与状态

使用一个保持源宽高比的 Canvas, 不把显示尺寸作为其像素分辨率。首次 small full 显示后可以点击放大, 立即用已有图填充放大视图, 等待 detail full 替换; 在新图提交前保留加载状态。退出放大同理。

优先 `createImageBitmap` 解码, 不支持或失败时使用 Blob URL + `Image` 的受控后备。同一批的所有块验证并解码成功后, 在一次同步绘制任务内提交, 再 ACK; 异步图片完成顺序不能决定提交顺序。解码期间收到 epoch 切换则取消/丢弃旧任务, 不得把旧 tile 画入新图。绘制异常则将基准标为无效并 resync, 不继续应用后续 delta。

使用 staging canvas 或等价完整批次提交机制; full/分辨率变化会重建画布, 不能保留前代像素。及时 `ImageBitmap.close()`、回收 Blob URL 和临时对象, 页面隐藏后不继续解码。需要本地放大时允许浏览器手势或本地变换, 不转发 Guest `scroll`/`drag`。

必须覆盖 `connecting`、`live`、`idle`、`reconnecting`、`paused`、`guestUnavailable`、`permissionRequired`、`vmStopped`、`expired` 状态。无新图不意味着断线; 分别维护最近有效 Guest 检查、传输心跳和内容变化时间。Guest 健康检查间隔 <= 3 秒, 不能只依据 WSS 心跳显示 live。

网络断开/VM 暂停时可保留最后一帧, 但必须标记为旧画面。权限撤销、退出登录或授权会话过期时清空像素与缓存, 不继续展示敏感截图。`visibilitychange`/`pagehide` 尽力 pause, 服务端租约和超时兜底; 恢复前台必须新代次完整同步。应用层心跳必须经页面 JS 回复, 不能用浏览器自动响应的 WS 控制帧证明页面仍在消费。

## 8. 只读安全与生命周期

建议入口为 `terminal-mac observe [NAME] --bind 127.0.0.1 --port 0`, 前台运行并在退出时撤销所有会话, 不依附 MCP 会话。端口 0 表示系统分配并输出实际地址。默认只绑定 loopback; 外部访问通过用户明确配置的 HTTPS 反向代理, 不自动暴露到公网。静态页和 WSS 使用同源地址。

安全验收不以“前端没有按钮”代替后端能力限制:

- Web 后端只持有观察服务能力, 仅可请求预定义的 Guest 观察/状态消息。输入、生命周期控制、文件读写、通用 action 转发一律不存在或拒绝。
- 继续执行 `GuestGuard.requireVirtualMac`; Guest 无响应时绝不截取 Host 桌面作为后备。权限提示不得要求只读用户开放 Accessibility。
- 服务生成 >= 128-bit 随机、5 分钟有效的一次性配对令牌, 绑定当前 VM。分享地址放在 fragment 中, 页面取得后立即清除地址栏 fragment, POST 到同源会话端点兑换; 不把令牌放查询参数、日志或 localStorage。
- 兑换后使用随机服务端会话 + `HttpOnly; Secure; SameSite=Strict` Cookie, 最长 60 分钟, 可主动撤销。不同手机需各自配对, 不重放同一个一次性令牌。活动 WS 也必须受服务端过期/撤销定时器约束, 不仅在握手时鉴权。
- 手机路径必须 HTTPS/WSS; 明文只允许显式开发模式的 loopback 本地测试, 不允许用关闭 Secure Cookie 的方式对外部署。不要跳过 TLS 证书校验。
- 受保护 HTTP 接口和 WS 均检查授权; 无截图内容的静态配对页面与令牌兑换端点允许未建立会话的访问。兑换 POST 和 WS 升级校验精确的 Origin allowlist, 拒绝缺失/`null` Origin 的浏览器观察请求。设置 Host allowlist, 不信任任意客户端 `X-Forwarded-*`; 代理配置必须明确。
- 配对失败按令牌/来源限速, 默认每来源每分钟最多 5 次, 且有全局上限。鉴权通过前不启动 Guest 捕获或进行图片编码。
- 截图、会话接口返回 `Cache-Control: no-store`; 页面设置 CSP、禁止第三方脚本、`frame-ancestors 'none'`、`Referrer-Policy: no-referrer`。不注册保存截图的 Service Worker。
- 不提供任意本地文件服务或 mailbox 路径。仅打包资源可被静态访问, 拒绝目录穿越。图像文件名必须匹配内部请求 UUID, 读取使用既有 `Mailbox` 防护并限制解压后大小。
- 默认不把图像或令牌写入日志、遥测和持久缓存。共享目录临时图用完删除; 迟到回复和异常退出由会话命名空间内的有界清理器回收, 不扫描删除其他调用者的文件。

关闭/隐藏手机只停止该订阅, 不停止 VM。服务端收到最后一个 pause/close 后, Web 源流在 15 秒内停止; 终端自己的查看和控制保持原样。只有已声明后台的标签页时可保留轻量心跳, 但不得继续截屏、编码和刷新图片文件。若系统冻结页面而 pause/close 未送达, 允许先等待 45 秒应用心跳超时, 加停止宽限后的总兜底时间 <= 60 秒; 不能声称此不可见事件也能在 15 秒内被可靠感知。

## 9. 指标与实现顺序

指标仅采集数值, 不上传屏幕内容或秘密。按 VM/档位统计捕获帧数、未变帧数、候选/实际变化 tile 数、覆盖率、full/delta 字节数、整帧选择原因、完整刷新原因、编码时间、socket 待写字节、ACK 时延、超时数、活跃订阅、缓存大小和租约状态。

Guest -> Host 和 Host -> 手机分别计数。浏览器记录解码/绘制耗时、丢弃的旧代次任务和资源释放情况。`recv -> draw` 不是端到端时延; 跨设备墙钟不能直接相减, 端到端测量需同步时钟并记录误差, 或外部拍摄/测试图事件标记。

| 阶段 | 开发交付 | 出口条件 |
| --- | --- | --- |
| P0: 正确性模型 | 协议类型、尺寸校验、tile/revision/ACK 状态机、合成图测试 | 不依赖真实 Guest 即可验证丢帧合并与恢复 |
| P1: 只读完整链路 | 隔离观察流、能力协商、安全 Host 服务、手机完整 PNG + ACK | 首帧、状态、鉴权、只读边界通过; 只是中间里程碑 |
| P2: 差分与带宽 | dirty 历史并集、tile 去重、每客户端基准、回退与背压 | 与整帧 oracle 一致, 稀疏场景明显节流 |
| P3: 生命周期 | 全屏、前后台、重连、模式竞争、慢客户端、多观察者 | 无错误像素、无无限队列、无终端回归 |
| P4: 发布验收 | 真 Guest + iPhone/Android、弱网、性能与安全证据 | 第 10/11 节必须项通过, 更新验收记录 |

P1 仅便于分步交付, 不能当作已满足本方案的最终版本。更换 JPEG/WebP 或引入 WebRTC 必须另开决策, 不能通过无声降质掩盖带宽问题。

## 10. 功能与安全验收矩阵

纯算法测试使用固定像素 oracle: 把发送批次应用到客户端模拟图, 结果必须等于该批次快照对应的完整目标图。浏览器测试用同一解码/色彩路径加载完整 PNG 作为 oracle, 避免把不同色彩管理路径差异误判为 delta 错误。

| ID | 场景与操作 | 必须通过 |
| --- | --- | --- |
| F01 | 首次连接, 首帧到达前即切换 detail | 最终档位 full 才成为基准, 无跨代 tile |
| F02 | 单个区域改色/追加文字, 连续 100 次; 最后一次落在限流等待期 | 客户端结果逐批等于 oracle, 未变区域不污染, 停止变化后最后状态也必达 |
| F03 | A 后跳过 B/C, D 到达; 三次改不同位置 | 三处最终状态全部同步, 不仅 D 的脏区 |
| F04 | 编码/等待 ACK 时再次改变同一 tile | ACK 后新 revision 仍待发送, 不丢最后一次变化 |
| F05 | A -> B -> A, 重叠 dirtyRects, 区域反复移动 | 无残影; 多发可接受, 漏发不可接受 |
| F06 | 历史淘汰、dirtyRects 缺失/非法、基准未知 | 全图比较/full 恢复, 不把未知当作未变化 |
| F07 | Retina/非 Retina、缩放、非整数脏区、边缘 tile | 坐标正确; 字体边沿、最后一行/列与 oracle 一致 |
| F08 | 整屏滚动、窗口移动、大面积更新 | full 回退有效, 面积不重复计算, 不无限堆积 |
| F09 | PNG 解码延迟乱序、某一块损坏 | 无半帧正常 ACK; 失败 resync, 内存被回收 |
| F10 | 断网恢复、旧 ACK、未来 ACK、重复 ACK | 不能错误推进基准; 恢复首先 full |
| F11 | 连续全屏/退出/旋转 30 次, 旧回调晚到 | 最终配置正确, 无旧尺寸/代次混用 |
| F12 | 手机锁屏/后台 60 秒再恢复 | 停止不可见图像工作, 恢复 full 且正确显示 |
| F13 | Guest helper 重启、崩溃、VM 暂停/停止 | 状态真实, 新代次恢复; 不显示 Host 截图 |
| F14 | Screen Recording=false 或撤销; Accessibility=false | 前者阻止/清屏, 后者不妨碍只读观看 |
| F15 | 一个快手机、一个延迟 ACK 8 秒的手机 | 快端继续更新, 慢端仅一个在途批次 |
| F16 | 手机与原终端 viewer 同时运行、分别关闭 | 尺寸/生命周期隔离, 原输入和截图语义不变 |
| F17 | 10 分钟静止, 排除光标/时钟/动画 | 首帧后图像消息数为 0, 健康状态仍准确 |
| S01 | 未鉴权受保护 HTTP/WS、错误 Origin/Host、令牌重放 | 拒绝, 不采集、不编码、不返回像素 |
| S02 | 未兑换配对令牌过期、授权会话到期、服务退出/撤销 | 拒绝过期配对; 活动会话到期也断开/清屏, 不能继续请求图像 |
| S03 | 注入 click/type/scroll/stop/action 等消息 | 不触发 Guest/Host 输入或生命周期动作 |
| S04 | 目录穿越、符号/硬链接、伪造图片文件名 | 既有 mailbox 防护继续生效, 无任意文件读取 |
| S05 | 超长 JSON、超大 WS 分片、溢出 offset/尺寸、解压炸弹 | 在分配大内存或解码前拒绝, 服务继续可用 |
| S06 | 第 5 个连接、控制消息洪泛、模式/重同步洪泛 | 拒绝或限速, 不突破连接/编码/内存预算 |
| S07 | 扫描日志、缓存、分享 URL 请求记录 | 无图像正文/令牌, 无意外持久缓存 |
| S08 | Host 服务崩溃、Guest 迟到回复、连接异常退出 | 租约回收, 临时文件有界且只清理自身命名空间 |

模式/重同步等高成本请求默认每连接每秒最多 2 次、突发最多 4 次, 其余合并或拒绝。普通控制消息另设每连接每秒 20 条上限, 避免应用层 JSON 解析洪泛。

自动化至少包括 Swift 单元测试、Guest/Host 假 transport 集成测试、真实浏览器 Canvas 对照测试。Playwright 的移动 viewport 不能代替 iOS Safari/Android 真机解码、后台冻结和功耗测试。

## 11. 性能、带宽与真机验收

### 11.1 固定工作负载

每次记录 Host/Guest 机型与系统、Guest 点/像素尺寸、是否 Retina、字体、浏览器/手机系统、目标分辨率、tile、编码器、FPS、网络条件和测试时长。每档至少跑 10 分钟, 明确排除启动预热的统计范围。

| 工作负载 | 规定内容 | 主要指标 |
| --- | --- | --- |
| 静止 | 固定终端/状态页, 关闭光标闪烁、时钟和动画 | 首帧后图像 0 B, CPU、采集与健康检查开销 |
| 稀疏更新 | 固定 640x400/1600x1000 页面, 每秒一次计数文字变化; 每次 <= 2 个目标 tile, 不滚动 | 实际 KB/变化、平均码率、相对整帧节省 |
| 普通日志 | 每秒追加 1 行, 达底后发生真实滚动 | 带宽分布、full 比率、文字清晰度 |
| 滚动压力 | 连续滚动 60 秒 | 队列有界、full 退化、时延、降 FPS |
| 多客户端 | 同 VM small/detail 各 1, 加一个慢端 | 编码复用、每连接带宽、快端不受慢端阻塞 |

差分基线必须是 **同目标图像、同 PNG 编码器、同捕获事件/发送机会** 的整帧方案。通过记录/回放同一测试快照序列进行 A/B, 保留首帧、重同步和控制流量单独统计, 不与“不停重发静态图”的低效基线比较后声称收益。

### 11.2 初始门槛

这些是开发目标, 不是已经实测达标的承诺。更改门槛需在验收记录解释原因。

| 指标 | 验收目标与条件 |
| --- | --- |
| 正确性 | 无损算法 oracle 零像素差异; 浏览器同路径 oracle 无差分造成的差异 |
| 稀疏更新带宽 | 排除首帧后, 相对同事件整帧 PNG 减少 >= 80%; small <= 0.25 Mbps, detail <= 1 Mbps |
| 完全静止 | 10 分钟内首帧之后不发送任何图像批次; 控制流量另计 |
| 首帧 | Guest 已就绪、鉴权完成、RTT <= 30 ms/可用吞吐 >= 10 Mbps, p95 <= 2 秒 |
| 更新可见延迟 | 同网络、稀疏负载: small p95 <= 750 ms, detail p95 <= 500 ms |
| 手机解码+提交 | 参考真机 small p95 <= 50 ms, detail p95 <= 100 ms, 记录实际机型 |
| 弱网 | 1 Mbps/RTT 150 ms/1% 丢包, 正确性通过、无旧帧长队列; 网络恢复后含退避 <= 22 秒恢复 small 最新画面, 重连成功后 <= 5 秒; detail 超预算按策略降档 |
| 资源释放 | 最后一个 pause/close 收到后 <= 15 秒停止 Web 捕获, 无新增截图文件; 冻结且通知丢失的兜底 <= 60 秒 |
| 内存稳定 | 30 分钟压力与 30 次模式切换后无持续增长; 预热后相同静止态末尾占用比起点增长 <= 10 MiB |
| 内存预算 | 每 VM 新增 Host 观察内存目标 <= 256 MiB, 手机页面目标 <= 128 MiB; 记录峰值与平台测量方法 |

Host/Guest CPU、手机电量/温度需与同设备同亮度的静态页面和整帧方案分别对照, 记录原始值; 暂不虚构跨设备统一的“CPU < 5%”或“更省电”结论。无图像网络流量也不代表 capture/compositor/心跳 CPU 为零。

网络至少覆盖稳定 Wi-Fi、上述受限网络、断网 15 秒后恢复; 浏览器至少覆盖一台真实 iPhone Safari、一台真实 Android Chrome, 另用桌面浏览器做协议自动化。TLS 代理路径和本地开发路径分别测试。

### 11.3 发布记录模板

实施完成后新增独立的验收记录, 不改写 [VALIDATION.md](VALIDATION.md) 的历史结果来伪装本功能已验收。记录必须包含:

- 提交版本、构建/Guest helper 版本、测试设备和协议参数。
- 第 10 节各 ID 的 pass/fail/blocked, 测试命令和证据位置。
- 每档 PNG full/tile 的实际字节分布 (p50/p95), full/delta 数量, 首帧与稳态字节数, 每小时流量外推的假设。
- 带宽、时延、编码/解码时间、CPU/内存、弱网恢复曲线; 失败项和已知限制。
- 图片对照仅使用可公开的合成内容或经过明确授权的测试 Guest; 不将真实凭证/个人桌面写入仓库。

完成标准: P0-P4 交付, F/S 必须项通过, 性能门槛达到或获得有记录的范围调整。不得把文档、合成 PNG/JPEG 文件大小测试或静态页面演示当作完整功能验收。
